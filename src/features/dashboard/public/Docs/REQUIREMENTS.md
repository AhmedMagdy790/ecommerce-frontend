# المتطلبات الوظيفية (Functional Requirements)

## 1. إدارة المستخدمين (User Management)
- [ ] السماح للزائر بتصفح الموقع دون الحاجة لتسجيل دخول.
- [ ] إمكانية إنشاء حساب جديد (الاسم، البريد، كلمة المرور).
- [ ] تسجيل الدخول والخروج.
- [ ] إدارة ملف العميل (تعديل العنوان، رؤية الطلبات السابقة).

## 2. عرض المنتجات (Catalog Management)
- [ ] عرض قائمة المنتجات مع الصور والأسعار.
- [ ] البحث عن منتج بالاسم.
- [ ] تصفية المنتجات (Filtering) حسب التصنيف أو السعر.
- [ ] صفحة تفاصيل المنتج (الوصف، المواصفات، الكمية المتاحة).

## 3. سلة التسوق (Cart System)
- [ ] إضافة منتج للسلة (سواء كان المستخدم مسجلاً أو زائراً).
- [ ] تعديل كمية المنتج داخل السلة.
- [ ] حذف منتج من السلة.
- [ ] حساب الإجمالي (Subtotal) وتطبيق الضرائب إن وجدت.

## 4. إتمام الطلب (Checkout Flow)
- [ ] اختيار عنوان الشحن.
- [ ] اختيار طريقة الدفع.
- [ ] تأكيد الطلب وإرسال إشعار (أو عرض صفحة نجاح العملية).
- [ ] (إضافي) حفظ الطلب في سجل طلبات المستخدم.

## 5. نظام الطلبات (Order System)
- [ ] تغيير حالة الطلب (قيد الانتظار، تم الشحن، تم التوصيل).
- [ ] تتبع حالة الطلب من قبل المستخدم.




## 6. المتطلبات غير الوظيفية (Non-Functional Requirements)

### أ. الأداء (Performance)
- **وقت الاستجابة:** يجب ألا تتجاوز مدة تحميل الصفحة الرئيسية ثانيتين (2s).
- **الاستعلامات:** تحسين سرعة استعلامات قاعدة البيانات (Database Indexing) لتجنب بطء البحث.
- **التخزين المؤقت (Caching):** تفعيل Redis لتخزين بيانات المنتجات الأكثر طلباً لتقليل الضغط على قاعدة البيانات.

### ب. الأمان (Security)
- **المصادقة:** حماية جميع الـ API Routes (باستثناء التصفح العام) باستخدام Token-based Authentication (مثل Sanctum).
- **المدخلات:** تعقيم جميع مدخلات المستخدم (Input Sanitization) لمنع هجمات الـ SQL Injection و XSS.
- **التشفير:** استخدام HTTPS في جميع مراحل الاتصال.

### ج. القابلية للتوسع (Scalability)
- **بنية الكود:** اتباع مبادئ الـ Clean Architecture لفصل المنطق البرمجي (Business Logic) عن واجهة العرض (UI)، مما يسهل إضافة ميزات جديدة لاحقاً.
- **فصل المهام:** توزيع العمل (مثلاً: إرسال بريد إلكتروني أو معالجة صور) على نظام طوابير (Queues).

### د. تجربة المستخدم (Usability & Accessibility)
- **التجاوب:** دعم العمل على جميع الشاشات (Mobile, Tablet, Desktop) بنسبة 100%.
- **سهولة الاستخدام:** توفير رسائل خطأ واضحة للمستخدم عند فشل أي عملية (مثل خطأ الدفع).

### هـ. الموثوقية (Reliability & Observability)
- **التسجيل (Logging):** تسجيل الأخطاء البرمجية (Errors) بشكل دوري لمعرفة سبب أي فشل في النظام.
- **التوافر:** الحفاظ على الموقع متاحاً بنسبة 99.9% من الوقت.
